FreeLLM Swarm

Claude supervises, free LLMs build

Orchestrate parallel AI workers via OpenAI-compatible endpoints. A supervisor (Claude Code) splits tasks, streams worker output, reviews revisions, and applies approved changes — all logged for full transparency.

Quick Start GitHub Repository

How It Works

The supervisor–worker loop: Claude Code breaks a project into tasks, spawns FreeLLM API workers in parallel, streams their output, reviews it, and iterates until satisfied.

📝 Events Log

Every action written to .swarm/<run>/events.jsonl — structured, append-only, queryable.

📄 Live Markdown

Per-task live.md updated in real time — watch workers think and code.

🔒 Read-Only Dashboard

Live web UI over the run data — never modifies the swarm directory.

Quick Start — swarm.py

Get the orchestrator running in three steps.

1. Configure API Access

Set the FreeLLM API endpoint and key (or use the config file):

export FREELLMAPI_URL="https://api.freellm.example/v1"
export FREELLMAPI_KEY="sk-..."

Alternatively, create ~/.config/freellmapi/key with the token (one line).

2. Define Tasks

Create a tasks.json describing the work:

{
  "project": "my-app",
  "tasks": [
    {
      "id": "backend-api",
      "prompt": "Create a FastAPI REST API with /health and /items endpoints...",
      "model": "llama-3.1-70b",
      "files": ["app/main.py", "app/schemas.py"]
    },
    {
      "id": "frontend",
      "prompt": "Build a React + Vite frontend that consumes the API...",
      "model": "llama-3.1-70b",
      "files": ["frontend/src/App.jsx", "frontend/src/api.js"]
    }
  ]
}

3. Run the Swarm

python swarm.py tasks.json

This creates a run directory under .swarm/<timestamp>/ with per-task folders, events.jsonl, and live.md files.

Supervisor Commands (interactive)

While the swarm runs, the supervisor (you / Claude Code) can intervene:

revise <task> <feedback>

Send feedback to a worker; it re-generates with the new context.

note <task> <text>

Log a supervisor observation without triggering a revision.

verdict <task> accept|reject

Mark a task's output as accepted or rejected.

apply <task>

Copy staged files from .swarm/<run>/<task>/staged/ into the working tree.

Watch Live

# Tail a task's live markdown
tail -f .swarm/<run>/<task>/live.md

# Or open the dashboard (see Deployment)
open http://localhost:8787

The Dashboard

A read-only, real-time web UI for monitoring runs — built with Python stdlib, zero dependencies.

📊 Run Overview

GET /api/runs — summaries of all runs, newest first. Status, task counts, token totals, duration.

🔍 Run Detail

GET /api/runs/<run> — full state: all tasks with last 300 events, staged files, live markdown.

📈 Aggregated Stats

GET /api/stats — cross-run totals: tokens by model, task outcomes, worker throughput.

⚡ Live Events (SSE)

GET /api/events — Server-Sent Events stream. New events push instantly to the browser.

🔐 Token Auth

Optional DASHBOARD_TOKEN via ?token= or Authorization: Bearer. Static files stay public.

🛡️ Hardened Headers

CSP, X-Frame-Options: DENY, Referrer-Policy: no-referrer, rate limiting on /api/.

Local Dev Run

SWARM_DIR=.swarm PORT=8787 DASHBOARD_TOKEN=changeme python -m dashboard.server

Deployment

Production-ready options. Always set a long random DASHBOARD_TOKEN and terminate TLS.

Docker (Recommended)

Build from the project root (context is the repo root, not dashboard/):

docker build -f dashboard/Dockerfile -t swarm-dashboard .

Run with the swarm directory mounted read-only:

docker run -d --name swarm-dashboard \
  -p 8787:8787 \
  -v /host/path/to/swarm:/data/swarm:ro \
  -e SWARM_DIR=/data/swarm \
  -e HOST=0.0.0.0 \
  -e PORT=8787 \
  -e DASHBOARD_TOKEN="$(python3 -c 'import secrets;print(secrets.token_urlsafe(32))')" \
  swarm-dashboard
  • Container runs as non-root user dashboard
  • Healthcheck polls /healthz (works with token auth)
  • Exposes port 8787; put behind nginx for TLS

systemd on Debian/Ubuntu or Proxmox LXC

  1. Clone the repo to /opt/freellm-swarm: 
    git clone https://github.com/fr3e1/freellm-swarm.git /opt/freellm-swarm
  2. Generate a token: 
    python3 -c 'import secrets;print(secrets.token_urlsafe(32))'
  3. Install the unit (copy and edit): 
    sudo cp /opt/freellm-swarm/dashboard/swarm-dashboard.service /etc/systemd/system/
sudo mkdir -p /etc/systemd/system/swarm-dashboard.service.d
    Create /etc/systemd/system/swarm-dashboard.service.d/override.conf: 
    [Service]
Environment=SWARM_DIR=/data/swarm
Environment=DASHBOARD_TOKEN=your-generated-token-here
WorkingDirectory=/opt/freellm-swarm
  4. Ensure the swarm directory exists and is readable: 
    sudo mkdir -p /data/swarm
sudo chown -R $(whoami):$(whoami) /data/swarm
  5. Enable and start: 
    sudo systemctl daemon-reload
sudo systemctl enable --now swarm-dashboard

The unit uses DynamicUser=yes, ReadOnlyPaths=/data/swarm, and extensive hardening (ProtectSystem=strict, NoNewPrivileges=yes, etc.).

nginx Reverse Proxy + TLS

  1. Copy the example config: 
    sudo cp /opt/freellm-swarm/dashboard/nginx.conf.example /etc/nginx/conf.d/swarm-dashboard.conf
  2. Edit /etc/nginx/conf.d/swarm-dashboard.conf:
    • Replace server_name _; with your hostname
    • Uncomment the TLS server block (port 443)
    • Point ssl_certificate and ssl_certificate_key to your certs (e.g. Let's Encrypt)
  3. Test and reload: 
    sudo nginx -t
sudo systemctl reload nginx

Key nginx Settings (from example)

  • SSE-friendly: proxy_buffering off, proxy_read_timeout 1h, X-Accel-Buffering: no
  • Token-safe logging: Custom log_format uses $uri (path only) — ?token= never hits access logs
  • Rate limiting: limit_req_zone at 30 req/s per IP, burst 50 on /api/
  • HSTS: Strict-Transport-Security: max-age=31536000 on TLS block
  • Security headers: X-Content-Type-Options, X-Frame-Options, Referrer-Policy added by nginx (with always flag)

Troubleshooting

🔴 SSE Stalls / Disconnects Behind Proxy

Cause: Proxy buffers the response or times out the connection.

Fix: Ensure nginx has proxy_buffering off, proxy_read_timeout 1h, and proxy_set_header X-Accel-Buffering no. For other proxies (Cloudflare, AWS ALB, etc.), disable buffering / enable streaming / set idle timeouts > 60s.

🔴 401 Unauthorized on API Calls

Cause: DASHBOARD_TOKEN is set but request lacks valid token.

Fix: Pass token via ?token=YOUR_TOKEN query param or Authorization: Bearer YOUR_TOKEN header. Generate a new one with python3 -c 'import secrets;print(secrets.token_urlsafe(32))'. Check the token matches exactly (no trailing newline).

🔴 Healthcheck Fails (Docker)

Cause: /healthz unreachable or returns non-200.

Fix: Verify container port 8787 is exposed. Test inside container: docker exec swarm-dashboard python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8787/healthz', timeout=5)". If token is set, healthcheck still works — it's unauthenticated by design.

🔴 Dashboard Shows No Runs

Cause: SWARM_DIR points to wrong path or directory is empty.

Fix: Confirm SWARM_DIR (or /data/swarm in Docker) contains .swarm/<run>/ subdirectories with events.jsonl. Run swarm.py at least once to generate data.

🔴 429 Too Many Requests

Cause: nginx limit_req zone exceeded (30 req/s per IP, burst 50).

Fix: Normal for bursty SSE reconnects. If persistent, increase rate or burst in limit_req_zone / limit_req in nginx config.

🔴 systemd Service Won't Start

Cause: WorkingDirectory missing, SWARM_DIR not readable, or Python module not found.

Fix: Check journalctl -u swarm-dashboard -f. Ensure /opt/freellm-swarm exists and dashboard/server.py is present. Verify ReadOnlyPaths=/data/swarm matches your mount.
